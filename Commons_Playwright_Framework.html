3 Two Run Modes

Single TC Run
Run one test case directly. Works for any TC — navigation, static pages, cart, login, or data validation.

Suite Run (Batch)
Run multiple TCs in one go from the master playlist file. Generates a summary report at the end.

4 Test Case Excel — One Sheet

Every TC is one Excel file with one sheet: Steps. Row 1 carries config values. Steps start from row 2.

Steps sheet columns # · Program · Input Excel · Max Pages · Max Rows · Action · Page · Object Name · Params · Filter · Notes

The Filter column is the key addition. On checkbox steps, tester writes key=value. The runner collects all Filter values as it executes steps, then uses them to build the Cypher WHERE clause.

#ProgramInput ExcelMax PagesActionPageObject NameParamsFilterNotes
1 CDS InputFiles/CDS/TC01_... 5 dismiss_popup Always first
2 click_and_wait NavBarCDS_Data-Btn Go to Data page
3 js_click_and_wait Data_pageFilter/PHS/phs001437_Chkbx phs=phs001437 Select study
4 js_click_and_wait Data_pageFilter/Sex/Unknown_Chkbx sex=Unknown Select sex
5 js_click_and_wait Data_pageFilter/Strategy/RNASeq_Chkbx strategy=RNA-Seq Select strategy
6 read_stat_bar CDS Read stat bar counts
7 multi_function ParticipantsTab Paginate + compare vs Memgraph

Filter values collect automatically as the runner clicks checkboxes. When multi_function runs, the runner builds WHERE phs='phs001437' AND sex='Unknown' AND strategy='RNA-Seq' and queries Memgraph — no tester involvement.

Standalone TCs (no data validation)

For navigation, static pages, cart, and login tests: just leave the Filter column empty on all steps. No multi_function step. Runner never calls Memgraph. Same Excel, same runner — the absence of Filter values is the signal.

5 One-Off Custom Queries

The standard flow builds a Cypher query from the template in query_builder.py using the Filter column values. This covers 99% of TCs.

For the rare case where the standard template does not work, the tester adds a Queries sheet to that specific TC Excel.

Rule: If a Queries sheet exists → use it. If not → use query_builder.py template. Tester adds a Queries sheet only when explicitly needed. Most TCs have no Queries sheet.

Queries sheet format (one-off only)

TabCypher Query
ParticipantsTab MATCH (p:Participant) WHERE p.special_field='X' RETURN p.id, count(*)

Framework developer or tester pastes the full Cypher directly. Runner uses it as-is for that tab, bypassing the template.

Where the Cypher template lives

Framework developer writes one template per tab per program in core/query_builder.py. Change the template once — all 100 TCs pick it up automatically. Tester never writes Cypher for standard tests.

# core/query_builder.py — framework developer writes once
CYPHER_TEMPLATES = {
    "CDS": {
        "ParticipantsTab": """
            MATCH (p:Participant)-[:FROM_STUDY]->(s:Study)
            {where}
            RETURN p.participant_id, s.study_name, p.gender
        """,
        "SamplesTab": """
            MATCH (sa:Sample)-[:FROM_PARTICIPANT]->(p:Participant)-[:FROM_STUDY]->(s:Study)
            {where}
            RETURN sa.sample_id, sa.sample_type, p.gender
        """,
    }
}

# Runner builds the WHERE clause from Filter column values in TC Excel:
# phs=phs001437, sex=Unknown, strategy=RNA-Seq
# → WHERE s.phs='phs001437' AND p.gender='Unknown' AND sa.strategy='RNA-Seq'
Filter key names must match the placeholder mapping in query_builder.py. Framework developer documents the allowed keys per program (e.g. phs, sex, strategy, disease). Tester uses those exact names in the Filter column.

7 Master Suite File — Batch Playlist Only

The master suite file is needed only when running multiple TCs in one batch. Single TC runs don't use it at all.

It is a simple playlist — no filter values, no query config. Everything that defines the test lives in the individual TC Excel.

9 How This Scales to 100+ Tests

Adding a new data validation test case

  1. Copy an existing TC Excel
  2. Change the filter checkboxes in the Steps sheet — update the Filter column values
  3. Add a row to the master suite file pointing to the new TC
  4. Done — no Python, no query writing

Updating the Cypher query for all TCs at once

Edit one template in core/query_builder.py. All TCs pick it up on the next run. No Excel files touched.

Adding a new program (e.g. CCDI)

  1. Create ObjectRepository/CCDI_ObjectRepository.xlsx
  2. Add URLs to config/settings.py
  3. Add Cypher templates to core/query_builder.py
  4. Create TC Excels — testers can start immediately
Bottom line for testers: Every new test case is a new Excel file + one row in the master. That's it. No code knowledge required.
